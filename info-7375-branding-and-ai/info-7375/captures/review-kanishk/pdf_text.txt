USER GUIDE & FEATURE OVERVIEW · V2 (FINAL EXAM SUBMISSION)
Find, Fix & Monitor Web Accessibility — Automatically
Paste a URL. AccessDrift launches a real headless Chrome, runs axe-core against the live page(s) across the full
WCAG 2.0/2.1/2.2 A & AA ruleset, and diffs the result against the last saved scan of that domain — so you find out
about the exact release that made things worse, not just today's score. 
Live: accessdrift-z1eh.onrender.com

The Drift Signal Framework
New — introduced this release, act now
Persisting — known, still open
Resolved — fixed and verified gone
Watch — model isn't confident; human-verify
Known Limitations (Honest)
No persistent disk on the live deployment — the free Render plan has no attached disk, so scan history resets on redeploy. Fine
for demoing one scan; not durable for long-term monitoring without a paid plan.
One DOM snapshot per page — axe audits the rendered DOM; it can't catch keyboard-trap or screen-reader-only issues that
need interaction.
Consent / bot walls — some sites (e.g. heavily CDN-protected domains) return an HTTP error to headless Chrome; the tool warns
rather than silently misreporting.
Score is a heuristic, not an official conformance grade — useful for tracking trends release over release.
AI fixes are optional — without ANTHROPIC_API_KEY set, every fix still works via the rule-based knowledge base; it just isn't
Claude-written.
